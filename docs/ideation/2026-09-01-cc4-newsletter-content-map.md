# cc4.marketing newsletter: content map + templates (adapted from The Vibe Marketer)

Companion to `2026-09-01-vibe-marketer-full-swipe-file.md`. This is the operational half: what our version looks like, issue by issue.

Rule zero: mimic the structure, formulas, and cadence. Never copy their prose or their content verbatim. Every issue must be grounded in cc4 assets (19 lessons, course skills, changelog, student builds) or our own experiments.

## 1. Positioning

They cover all AI marketing tools for all marketers. cc4 owns one wedge: Claude Code as the marketer's operating environment, taught free. Our equivalent of their "boring local business" proof engine is the cc4 site itself: we run the site, blog, SEO, analytics, and this newsletter with the same workflows we teach. Every issue can show receipts from our own repo.

## 4. Subject line rules (adopted)

Number + outcome first, contrarian negation second, "How I/we" third. Under 65 chars. Bank of seeds:
- "How we publish a blog post in one command" (publish-post skill)
- "Your prompts aren't the problem. Your context is."
- "One skill, 19 lessons, 0 dong: how cc4 stays free"
- "4 course workflows students are stealing this week"
- "We ran a full SEO audit with one slash command"
- "You finished Module 2. Now what?"
- "The newsletter you're reading was built by the course it teaches"

## 5. First 8 issues (alternating, weekly, Tue)

1. T: "This newsletter is built with the workflows it teaches." Dogfood issue, mirrors their Jul 28 repurposing issue: show the emails/ pipeline, Resend skill, give away a template. Establishes the meta-proof.

5. T: "3,200 pages" equivalent: our programmatic/SEO improvement plan (plans/20260804-seo-improvement-plan) as a walkthrough with before/after Search Console numbers.
6. E: "Context before agents" for course students: CLAUDE.md, brand files, memory. Ties to a specific lesson.

8. REC-style: one module deep dive (Module 2-7 service package, existing draft) with a free downloadable artifact; full materials link to the lesson.

## 6. Flywheel we can copy cheaply

- End every issue asking for builds; feature one named reader per roundup with a link. Zero cost growth loop, their strongest engine.
- Name our frameworks. A repeatable cc4 method deserves an acronym and a diagram; named frameworks become lessons, lessons become newsletter issues.
- Keep receipts public: every claim carries a number from our own repo/analytics.
- One asset, three touches: draft → blog post → newsletter issue → social atomization (they teach exactly this; we already have blog-drafts producing X threads + Substack variants).

## 7. Infra notes

- Stay on Resend + emails/ HTML pipeline + resend-email-campaign skill guardrails (dry-run, preview, per-turn send confirmation). Build one reusable skeleton template so per-issue work is content only.
- Poll: Resend has no native polls; use 3 tracked links to a thanks page (or mailto). Log clicks in analytics.
- "Read online": mirror each issue as a blog post; solves archive + SEO in one move (they use beehiiv's web version; ours is better because it feeds our own domain).
- Bilingual: EN default. VN variant only when the topic has a VN hook (precedent exists in emails/).
